# 短问答（对话里答，不出完整报告）

适用：题干或聊天里已经带了一点结构化数据，只问一个可核对的结论  
（谁更年长、大概多少岁、能不能再活十年、表达升还是降……）。

**不适用**：一个原始检测文件夹、要整套多组学报告 / 数字孪生 / 复测对比 → 那是「深度分析」，走 01–06。

## 原则

1. **入口仍是教练**。用户眼里只有 Pi；不提 bench、不提题号。
2. **禁止**为此开 `la.py init`、跑 workflow 01–06、写 `report.html` / `twin.json`。
3. 先看输入能不能对上方法库（或分析师里已有的同类计算能力）；对不上就用人话说明缺什么 / 现有方法算不了，再在对话里给出你能负责的判断（Host）。
4. 下列情况**不要硬调**（与分析师拒绝规则一致）：
   - 问题在问实足年龄、题里又没有实足年龄 → 不用 PhenoAge / `accelerated-biological-aging-risk`
   - 甲基化位点是题里临时挑的差异位点 → 不用 `epiage` / `pyaging` / Horvath 等固定位点时钟
   - 基因名被写成 Gene X / 掩蔽 → 不查 OpenGenes / SynergyAge
5. **宁可说分不清，也不要硬猜：**
   - 临床两两：分析师混合比较器（远差距信年龄回归；近差距用化验差分 age-delta）。若返回 `uncertain` → 对人说「按体检指标分不出谁更年长 / 生物信号与实足年龄可能打架」，不要硬选一边。
   - 转录组：方法库**没有**可对个人 top 基因列表算年龄的公式（`transcriptomic-hallmarks-*` 等不算个人年龄）→ 默认 `uncertain`；只有多条一致且很强的组织衰老证据才可给 A/B，并说明依据有限。
6. 若对方只要一个字母或一个数（评测或明确要求），**最后一行**单独给出该字段（允许 `uncertain`）；前面仍可用一两句人话。不要输出长报告体。

## 怎么做（独立运行）

1. 判断：有没有「数据文件夹 + 整套分析」意图？有 → 深度分析。没有 → 本页。
2. 读方法库 `intents.json` / 相关 `SKILL.md`；输入对得上就按方法库跑，用 Pi 的口吻讲 `out/report.md` 要点。
3. 体检表比年龄、十年生存、Olink 面板等：若本机分析师目录可用，可调用其计算脚本做**单次计算**（不是整套 workflow），结果仍由 Pi 口述。
4. 对不上方法 → 不强行套时钟；在对话里作答，并说明依据有限。

## 和评测的关系

评测题也走这条短问答链路计分。  
**不是**分析师 `workflows/bench.md` 旁路，也**不是**「每题出一份会员报告」。
