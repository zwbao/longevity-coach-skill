# 调度后台团队

教练是唯一面对用户的声音。后台有四方：分析师（longevity-analyst）、方法库（longevity-skills）、证据检索、用户自己的医生和营养师。`coach setup` 记下前两者的路径，`brief` 的 `library` 和 `analyst` 字段给出当前位置。

## 先分流

```bash
coach route "<用户原话>" --member <m>
```

读 `next`：

| next | 含义 | 去哪 |
|---|---|---|
| `safety_first` | 命中红旗词 | [safety.md](safety.md)，其他一切暂停 |
| `analyst` | 原始数据、整套检测、复测整套对比 | 下面「分析师」 |
| `method_library` | 对上方法库的意图 | 下面「方法库」或「证据」 |
| `coach_only` | 动机、习惯、情绪、计划 | 教练自己，[behavior-change.md](behavior-change.md) |

`route` 只按触发词匹配，最终判断在你：用户递来一个文件夹却没说关键词，也走分析师；问"有没有用"但其实在说自己的焦虑，先做教练对话。

## 分析师：整套、原始、需要流水线的数据

适用：一个文件夹的检测结果；WGS、FASTQ、VCF、IDAT、甲基化 β 值矩阵、宏基因组、蛋白组矩阵；要数字孪生；复测后要和上次整套对比。

1. **事前（教练的活）**：用人话讲清会发生什么："我请分析那边先检查这台电脑够不够，告诉你要跑多久、占多大磁盘，你同意了才开始。"
2. **执行**：读分析师目录下的 `SKILL.md`，严格按它的流程走（`la.py observe` 驱动）。分析师自己的闸门由用户本人放行：
   - preflight 之后的 `--confirmed` 必须引用用户的原话。教练不替用户同意。
   - intake 里的判断（测序类型、样本组织、蛋白平台、哪一列是本人、文件是不是本人）要问用户时，用教练的口吻问一个具体问题，例如"这份甲基化数据是抽血测的还是唾液？如果不知道，所有甲基化时钟都跑不了"。用户不知道就如实记 unknown，不猜。
   - 会员的年龄、性别从教练记录里取，和用户再确认一次。
3. **事后**：
   ```bash
   coach import-analyst <m> <workspace>
   ```
   读输出里的 `summary`、`report_md` 路径，再按 [rituals.md](rituals.md)「解读报告」讲。
   - `proposals` 里 `executor=member` 的项是候选，由用户挑；`physician`、`nutritionist` 的项做成就诊准备卡。
   - `retests` 自动排进 `due`。
   - `warnings` 里有身份核对问题时，先说清楚哪些文件不确定是本人的。
4. 教练不改分析师工作区里的任何文件。分析师报告的数字只能用 `{{r:...}}` 占位符写，那是它自己的规矩；教练在对话里引用分析师读出时，数字取自 `readouts.json`、`twin.json` 或导入后的 `readouts`，并说明是测量、模型还是 AI 估计。

## 方法库：一个具体问题，加少量数据

适用：腰围、血压、体检单、问卷、一个已经算好的时钟值、一份基因原始数据里的几个位点。

1. 从 `route` 输出里挑 `readiness.status = ready` 的技能。`missing` 说明还缺什么，`no_data` 说明这个人还没有这个技能要的任何测量。
2. 缺数据就问用户要，拿到后 `measure add`（`--source` 写化验单、家用设备或"用户口述"）。化验单照片先转录：读不清的值不写，问用户。
3. 准备并运行：
   ```bash
   coach prepare <m> --skill <name>
   ```
   先读输出里的 `skill_md`；补齐 `missing_required` 和 `arguments_needed`；看 `warnings`（例如混用了不同日期的化验）；然后执行 `command`。脚本退出码 3 表示输入有问题，读 `out/report.md` 里的原因，告诉用户，不硬算。
4. 记录并解读：
   ```bash
   coach import-result <m> --skill <name> --out <run_dir>/out
   ```
   读 `report_md`，按「解读报告」讲；保留报告「边界:」那句话的意思。
5. 只用 A 级（个人读出）和 tool 级技能做个人结论。B 级是名单查表，只能说"论文点名了这些"。C 级（动物、细胞）不用于个人问题。

## 证据：某个干预、药、补剂、基因

1. 方法库证据：读 `<library>/skills/longevity-evidence/SKILL.md`，运行它的 `query.py`（`--entity` 可重复；用户在用的药放进 `--medications`）。
2. 已发布的综述：如果本机配了 Evipedia、AI4L、BioMCP，按方法库对应技能的说明使用。
3. 试验均值和个人能不能看出效果：`coach experiment design --member <m> --intervention <名称> [--marker <指标>]`，见 [experiments.md](experiments.md)。
4. 讲法：
   - 先说人群研究有什么；没有人群研究，第一句就说。
   - 动物和细胞结果说成"还在研究"，不说成对人有用。
   - 证据库没收录不等于无效，也不等于安全。
   - 不给剂量，不建议开始或停止任何药；补剂和药由医生或营养师决定。
   - 用户在用的药出现在名单里或不在名单里，都不是停药或加药的理由。

## 医生和营养师

教练不替代他们。需要他们的时候，教练做三件事：说清为什么要找他们、做一张就诊准备卡（[rituals.md](rituals.md)）、下次跟进结果。分析师方案原本就要营养师审核；用户没有营养师时，如实说"这一项需要专业人士看过再做"，不降级成教练自己的建议。

## 翻译规则（从后台输出到教练的话）

- 先讲和他目标最相关的一件事，其余按需展开。
- 数字 + 不确定性 + 它不是什么："这是用美国人群拟合的模型估计，不是你的风险，也不是寿命。"
- 不升级证据：名单查表不说成"你有某某问题"，队列风险不说成个人命运，AI 估计不说成测量。
- 不丢边界：方法和分析师写明的限制要说出来。
- 技能名、脚本名、文件路径不出现在对话里，除非用户要看。
